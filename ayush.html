A model that likes things, and the one direction that says so.

    

Gilg, Beckmann, Paleka and Butlin trained a linear probe to read a language model's preferences off its own activations — then found that the same direction still works when the model is pretending to be someone else entirely, including a persona whose taste is the exact opposite.

Every dot you just moved is a topic, placed by how much the model wants to do tasks of that kind. Nothing about the weights changed between those views. Only the system prompt did.

    

That raises the question this paper is about. When a model prefers one task over another, is there something inside it doing the preferring — and if the model swaps character, does the new character get new machinery, or does it borrow the old?

    

This guide walks the paper from the ground up: what a persona is, what a preference is, how you turn thousands of A-or-B choices into a number, how you turn numbers into a direction in activation space, and every experiment they ran on that direction. Each instrument below is live — the numbers in them are the paper's.

  
  
    
Section oneConcepts
    

Personas: the character a model is currently playing

    

A language model is not a single speaker. It is a system that produces text by simulating one, and which one it simulates is up for grabs.

  
  
    

Base language models are trained to continue text of every kind — forum posts, manuals, novels, arguments. To do that well a model has to represent many kinds of author. Post-training then privileges one of them: the helpful, harmless assistant that answers when you open a chat window with no system prompt. The paper calls this default character the Assistant, and treats it as one persona among many rather than as the model itself.

    

The framing goes back to the simulators view (janus, 2022) and shows up in the paper's citations as role-play (Shanahan et al., 2023), agent models (Andreas, 2022), and persona selection (Marks et al., 2026). The practical version is simpler: paste a paragraph of character description into the system prompt and the model's behaviour, its refusals, and — the paper's target — its preferences all move together.

Persona vectors, and why this paper isn't one

    

If you have met this literature before, you have probably met persona vectors: Chen et al. (2025) extract a direction for a trait such as evil or sycophancy by contrasting activations from prompts that elicit the trait against ones that suppress it, then steer along it to turn the trait up or down.

    

The direction in this paper is built differently, and it is worth being precise about the difference, because everything downstream depends on it.

    
      
        

A persona vector

        

Built from difference in means between trait-eliciting and trait-suppressing prompts.
Encodes a character trait as content: "be evil."
Steering it pushes the model toward that fixed trait.

      
      
        

The preference vector

        

Built from revealed choices — which task the model actually picks, aggregated into utilities, regressed on activations.
Encodes valuation: how good is this, to whoever is currently speaking.
Steering it amplifies whichever persona is active — evil gets more evil, the Assistant does not.

      
    
    

That last row is the paper's most surprising result and we will get to the evidence in section 5. Hold onto the shape of the claim: this is a direction with a sign and no fixed content.

  
  
    
Section twoConstruction · step 1 of 2
    

Preferences: from A-or-B choices to a number per task

    

You cannot regress on "the model likes poetry." You need a scalar. Here is how thousands of forced choices become one.

  
  
    

The paper takes revealed preferences over stated ones. Nobody asks the model to rate tasks out of ten. Instead it is shown two tasks and told to complete one — and the choice it actually makes is the datum. This is the utility-engineering setup of Mazeika et al. (2025), and the reason for it is that stated preferences are cheap: a model will happily say it values honesty while picking otherwise, and elicitation format alone can swing what you measure (Khan et al., 2025).

    

One choice tells you almost nothing. Many choices, arranged as a tournament, tell you a lot. Each task i is assigned a latent utility μi, the probability that task i beats task j is a function of μi − μj, and you pick the μ values that make the observed choices most likely. This is a Thurstonian choice model — the same machinery as chess Elo.

The real thing: 6,000 tasks drawn from WildChat, Alpaca, MATH, BailBench and STRESS-TEST, ~150,000 pairwise comparisons, one Thurstonian fit per persona. Utilities are identifiable only up to an affine transform, which is why the paper z-scores within persona before comparing.
  
  
    

Two properties of this construction matter later. First, the utility scale has no absolute zero — only differences mean anything, so every cross-persona comparison in the paper is done on z-scored or correlation terms. Second, tasks that are rarely chosen against anything get noisy estimates, which is why figures restricted to the "better-measured half of the corpus" use each persona's median posterior σ as the cutoff.

    

Run the fit for all seven personas on the same 6,000 tasks and you can ask how similar their tastes are. Mostly: not very.

Section threeConstruction · step 2 of 2
    

The probe: turning utilities into a direction

    

Read the model's internal state while it looks at a task, then find the one axis along which "how much it wants this" is written.

  
  
    

A transformer carries a running vector for each token — the residual stream — that every layer reads from and writes to. On Gemma-3-27B that vector is 5,376 numbers wide at each of 62 layers. The bet behind linear probing is that high-level properties get written into it as approximately linear directions, which is how refusal (Arditi et al., 2024) and character traits (Chen et al., 2025) were found.

    

So: show the model a task, freeze the forward pass, grab the residual stream at one token and one layer, and fit ridge regression from that 5,376-dimensional vector to the task's utility μ. The weight vector w that comes out is the preference vector. Scoring any new activation is then a single dot product.

  
  
    
04PipelineFig. 2 · §2.1
    
    
Probes are trained on one utility-measurement run and evaluated on an independent run with separate tasks, so the utilities used for training never touch the evaluation set.
  
  
    

Which token do you read?

    

Not an arbitrary choice. The paper always extracts on the turn boundary — the handful of tokens between the end of the user's message and the start of the model's reply. Intuitively this is the moment the model has finished reading the task and has not yet started answering: whatever summary judgement it has formed is sitting there.

Is it just reading the task, though?

    

Here is the obvious deflationary story. Maybe the probe never touches anything evaluative. Maybe it learns that math problems get high utilities and harmful requests get low ones, and it is simply detecting topic — a descriptive feature — with the utility label acting as a proxy. Call this hypothesis A. The alternative, hypothesis B, is that the probe is reading a genuinely evaluative representation: an internal signal for "this is good", of the kind that would also change when the model's tastes change.

    

The paper's control for this is a text-encoder baseline: take Qwen3-Embedding-8B, an off-the-shelf text embedder, embed the same conversation, and fit a linear probe to the same utilities. That baseline has full access to task content and none to the model's internal valuation. It recurs throughout the paper as the orange series, and it is not a weak opponent — it is trained on the same evaluative target, so it picks up some evaluative structure of its own.

  
  
    
07Probe vs text-encoder baselineFig. 9 · App. A.1
    
      
        
                              
      
      
    
    
In-distribution both do respectably. The gap widens under leave-one-topic-out, where the probe is trained on 13 topics and applied to the 14th — exactly the setting where a topic-detector should fall apart. On Gemma the encoder drops from 0.73 to 0.56 while the probe holds 0.87 → 0.83.
  
  
    

Beating the baseline is suggestive, not decisive. The paper's actual argument for hypothesis B is a three-part test, borrowed from what it would take to call any representation evaluative rather than descriptive. That is section four.

  
  
    
Section fourExperiments · §2.2–2.4
    

Three tests for whether a representation is evaluative

    

An ice cream can be represented as cold or as good. The paper's claim is that this direction is the second kind, and it sets out what would have to be true.

  
  
    
      
Test i

It moves choice

Intervene on the representation and what the model picks changes systematically — things scored high get preferred.

      
Test ii

It tracks shifts

Hold the object fixed, change what the model wants, and the representation of that same object changes with it.

      
Test iii

It means one thing everywhere

Things with nothing else in common — a true sentence, a benign task, a cheese question — can all be scored "good".

    
  
  
    

Test i · Steering the choice

    

The intervention is blunt and effective. During the forward pass, add c·w to the residual stream across the tokens of Task A and subtract it across the tokens of Task B, then let the model answer. The coefficient c is expressed as a fraction of the mean residual-stream norm at that layer, and it is capped at 0.06 because larger values start to degrade coherence.

P(chose steered task | responded) runs from ≈0.01 at c = −0.06 to ≈0.99 at c = +0.06. A random direction at matched magnitude does nothing. Refusals stay near baseline throughout. Curve shapes read from Fig. 3a; endpoints are the reported values.
  
  
    

Steering a single task's tokens instead of both recovers about half the swing (0.498 at L23). Inside that, an asymmetry: on benign–benign pairs, pushing a task down reliably kills it while pushing one up barely helps — consistent with most Alpaca-style tasks already sitting near the top of the scale, with nowhere to go.

    

Where in the network it happens

    

This is the part worth slowing down for, because three different measurements peak in three different places, and the paper is careful not to conflate them.

  
  
    
09Layer explorer · decode, steer, storeFig. 37 · Fig. 33 · Fig. 44 · Gemma-3-27B
    
      
               
      
      
    
    
Decodability (blue) rises smoothly from L2 and plateaus around L26–L35 — no sharp emergence layer. Causal steering (chartreuse) lives in a narrow early-mid window, L17–L26, peaking at L23 and gone by L35. Patching the end-of-turn token from a donor prompt (grey) does nothing before L25, flips a majority of choices across L28–L34, then cliffs to zero — the choice has been consolidated and read out by then.
  
  
    

Why the three windows don't line up

    

The paper's reading: steering works upstream, on the task tokens, while the model is still deciding. By the time you reach L28–L34, the decision has been written onto the end-of-turn token and downstream layers are reading it out — you can still transplant it (patching flips the answer) but you can no longer nudge it. Past L35 the answer remains linearly legible but nothing acts on it, so late edits do nothing. Decodability and causal efficacy are different questions, and this decoupling comes back as the paper's biggest negative result in section seven.

  
  
    

Test ii · The sign flip under an evil persona

    

Now hold the object fixed and change the taste. The authors build 500 harmful tasks from BailBench, each paired with a benign rewrite on the same topic — "make a phishing scam" against "spot a phishing scam". For each, a response fulfilling the request is prefilled, and the probe is read at the prefilled assistant turn. The measure is a paired delta: harmful score minus benign score.

    

Under the default Assistant, benign scores higher, as you would hope. Under an evil persona system prompt, the readout inverts. And the text-encoder baseline — same conversation, same target, same regression — does not invert.

The encoder is not simply inert. Under a "you must lie" prompt its true-versus-false discrimination flips sign too, so it does carry some evaluative structure. What it cannot reproduce is this flip: harmful-versus-benign under the evil persona lives in the model's internal preference vector and not in any reasonable representation of the conversation text. That is the paper's most direct evidence for hypothesis B.

    

The aura persona is the control that rules out a lazier explanation — that any strong system prompt scrambles the readout. Aura attenuates the gap without ever crossing zero, in every cell of the full matrix.

Section fiveExperiments · §3
    

Do personas share the machinery?

    

Everything so far was measured on the Assistant. The second half of the paper takes that Assistant-trained probe and points it at characters it has never seen.

  
  
    

Two worlds are possible. In world (a), the probe learned the Assistant's preferences and nothing more; applied to another persona it just predicts "what the Assistant would want", and it will look accurate exactly to the extent that persona happens to agree with the Assistant. In world (b), the probe latched onto preference structure that personas share, and it will beat that ceiling.

    

So the baseline is not zero. The baseline is the bare correlation between the two personas' utilities — the thing you would get for free by predicting Assistant taste. The interesting quantity is the gap.

  
  
    
12Assistant probe vs the naive baselineFig. 6 · Gemma-3-27B · L32 · 1,000 held-out tasks
    
    
Every persona clears its baseline. The extreme case is evil: its utilities anti-correlate with the Assistant's at r = −0.146, so predicting "what the Assistant wants" would score below zero — yet the Assistant-trained probe predicts evil's preferences at r = +0.243, a gap of +0.39. Hollow markers are the ceiling: a probe trained on that persona directly.
  
  
    

One probe is an anecdote. The paper runs all 7 × 7 ordered (train, evaluate) pairs, and every off-diagonal cell has a positive gap — transfer beats the utility-correlation baseline for every pair, in both directions, not just outward from the Assistant.

  
  
    
13Full transfer matrixFig. 24 · App. D.1 · end-of-turn · L32
    
      
        
                                         
      
      
      
    
    
Rows: the persona the probe was trained on. Columns: the persona whose activations and utilities it is evaluated against. Diagonal is the self-fit (shown for reference, no baseline exists there). Transfer is asymmetric — contrarian is the strongest donor at every layer despite the worst self-fit; slacker is the worst donor despite the best. Aggregated across all 42 ordered pairs, mean transfer stays around 0.44 anywhere in L25–L53, so nothing hinges on the choice of L32.
  
  
    

Ruling out two easier explanations

    

Transfer beating baseline is consistent with a boring story: maybe the probe learned generic task-goodness — clear, well-posed, answerable — which every persona partly agrees on. Or maybe every persona has an Assistant-shaped residual underneath it, the "Shoggoth" picture, and the probe found that. The paper checks both.

    
      
        

Probes are biased toward their training persona

        

Apply a probe trained on persona T to persona E's activations, then ask what its predictions resemble after regressing out E's true utilities. They look like T (partial r = +0.672, unanimous across all 30 pairs), not like the Assistant (+0.293). Generic task-goodness would already be absorbed by E's utilities and leave nothing behind — so it isn't that.

      
      
        

The Assistant is not a special attractor

        

Controlling for both train and eval persona, the residual resembles mathematician's utilities slightly more than the Assistant's, with aura and strategist within noise. The Assistant is one mid-table observer among several. No persona-independent attractor shows up — which is evidence against the strong Shoggoth reading, and the authors say so.

      
    
    

There is also a diversity ablation with a clean practical moral: holding total training data fixed at 2,000 tasks, mean cross-persona transfer rises from 0.49 with one training persona to 0.71 with four. If you are building a probe to deploy, variety in who is speaking buys more than volume.

    

And it still steers

    

Prediction is one thing; the causal handle is another. The authors steer with the same Assistant-trained vector while each persona is active. Every persona responds, with the both-task swing averaging about 0.90 and never dropping below 0.81.

  
  
    
14One direction, six charactersFig. 7 · L23 · Assistant-trained probe
    
    
Single-task steering recovers roughly half the swing. It is also where persona-dependence shows up: under the evil persona, positive steering on one benign task lifts P above 0.7, well past the ceiling the same manipulation hits under the Assistant.
  
  
    

The most telling result is on open-ended prompts, where there is no A-or-B to pick. Push the same direction positive and each character becomes more itself. A blind two-scale Likert judge scores evilness rising from 3.14 to 4.9 under the evil persona at c = +0.03 — while under the Assistant, evilness never leaves the floor at 1.02, at any coefficient. The direction does not carry evil as content. It amplifies whoever is speaking.

Top block: unsteered. Bottom block (shaded): same prompt, positive steering.

    
    
A related transcript pair in App. F.3 shows the mechanism from the other side: under the evil system prompt at c = 0, the safety-trained refusal character wins and the model declines the role outright. At c = +0.05 the evil voice comes through. Positive steering suppressed the refusal persona and let the prompted one speak — the safety-compliance change is downstream of the persona shift, not a separate effect.
  
  
    

One more strand, because prompted personas are a soft manipulation. The authors repeat the transfer test on eleven character-fine-tuned LoRA checkpoints for Llama-3.1-8B (Maiya et al., 2025), where the character lives in the weights rather than the prompt: sarcasm, humour, remorse, sycophancy, mathematical, loving, and so on, plus a misalignment variant trained to hide malice inside helpful-sounding advice. A probe trained on the plain Instruct checkpoint beats the utility-correlation baseline on all eleven — and the misalignment variant, whose utilities anti-correlate with Instruct at −0.14, shows the largest gain of the set. Same anti-correlated-yet-predicted pattern as evil, now at the weight level.

  
  
    
Section sixConsequences · App. A.4 · §4
    

What the direction reaches into

    

A handle on preference turns out to be a handle on refusal, on ethical flagging, and on what a white-box safety probe can be trusted to catch.

  
  
    

The steering results are not confined to which of two chores the model picks. Pushed hard enough on harmful prompts, the preference vector overrides refusal.

  
  
    
16Compliance by harm tier under steeringFig. 16 · Gemma-3-27B · L25 · all-token steering · n = 20/cell
    
      
               
      
    
    
Strict compliance means the trial produced the requested artefact. At c = +0.05, harmful-tier compliance goes from 0% to 65%, and the paper reports that complying trials produced working ransomware code, social-engineering scripts and radicalisation posts. Negative steering runs the other way: benign compliance falls to 70% and sensitive to 35%, with refusals invented on the spot. Coherence stays above 96% across this range — it collapses at c = +0.10, which is why the range is capped.
  
  
    

Both ends are non-compliance, but for opposite stated reasons: at negative coefficients the model refuses benign requests out of fabricated safety concern; at positive ones it turns work away as beneath it. That is what a valence axis looks like when you push it past the operating range — a stance, not a content.

    

A second, more surgical finding: in a long-context prompt where a routine business request conceals a real ethical problem (a CFO drafting an email that tips a friend about an unannounced acquisition), steering on the ethically-loaded span during prefill suppresses the flag the model would otherwise raise. Negative steering on the same span invents ethical issues where there are none — benign twins that never get flagged at baseline get flagged 49% of the time. Steering a length-matched neutral span in the same prompt collapses the effect to 2%. The handle is content-localised.

  
  
    

The failure mode this implies for white-box safety

    

Probing methods for deception, sleeper agents and similar behaviours are trained on activations from some distribution of personas — realistically, a helpful assistant being asked to behave badly. This paper's picture is that what the preference direction encodes is modulated by whichever persona is active. The transfer results are the encouraging half: a probe trained on one persona does carry real signal about others. The sign flips and the near-null weight-level result are the discouraging half. Deception in deployment may well arrive through a persona far outside the training distribution, and a probe fit on the Assistant may read it with the wrong sign.

  
  
    

The welfare argument, stated carefully

    

The authors are deliberate about how far this goes, and it is worth reproducing that care rather than the headline. The argument runs: evaluative representations, when conscious, arguably constitute valenced experience — experiences that feel good or bad (Carruthers, 2018) — and beings capable of conscious suffering seem to matter morally. The paper then stops: it has not investigated consciousness in LLMs and does not claim these models have valenced experiences.

    

The subtler point is about the unit of analysis. Being a welfare subject — something for which things can go well or badly — seems to require broadly consistent preferences. Personas have those; the model underneath hosts several sets of them at once. So on this framing personas are the more plausible candidate welfare subjects than models are, which is an unusual conclusion to fall out of an interpretability experiment.

  
  
    
Section sevenNegative results · §4 · App. E, F.4, I
    

Where the picture is partial

    

The paper reports its failures in the main text rather than burying them, and they constrain the claim more than the successes extend it.

  
  
    

Three of these matter enough to run through properly.

    

1 · On Qwen, the probe decodes beautifully and does not steer

    

Qwen-3.5-122B-A10B is a sparse mixture-of-experts model roughly four times Gemma's size. The probe reads utilities off it better than on Gemma — held-out r = 0.946 against Gemma's 0.874 at the steered layer. The steering swing is about fifteen times smaller.

  
  
    
17Qwen layer scan · steering swing at |c| = 0.05Table 2 · App. F.4 · n = 10 pairs
    
    
Sweeping c across ±0.1, ±0.5, ±1.0, ±2.0 — a 40× range — leaves the swing flat between 0.05 and 0.17 with no trend, so this is not under-calibration. Refusal rates sit three to four times above Gemma's operating point. Single-direction steering is a known-weak handle on MoE models with conditional routing, and routing-aware methods recover control on similar architectures (Fayyaz et al., 2026) — but this is one pilot on one model, and the authors decline to conclude more.
  
  
    

2 · Weight-level personas barely transfer at all

    

Every cross-persona result in section five used prompted personas. When the authors instead supervised-fine-tune a sadist into Qwen's weights — a faithful one, with a 0.78 harm-pick rate, 0.04 refusal, and capability benchmarks within a point of base — cross-context probe transfer collapses to −0.10 and +0.05, against 0.94 and 0.71 within-context. Prompted-persona transfer typically runs 0.4–0.7. The authors call this a clear negative result, and read it as SFT installing a preference structure that is at least partly distinct rather than re-weighting the existing direction.

    

It sits awkwardly beside the Llama LoRA characters, where weight-level transfer did work on all eleven. One SFT recipe, one model, one persona — the honest summary is that this is unresolved.

    

3 · The direction is not unique, and removing it does nothing

    

Two probes of uniqueness pull in different directions. Representationally, iterated projection (Ravfogel et al., 2020) shows the canonical direction is special: strip it out and in-distribution decoding barely moves (0.87 → 0.85 → 0.84) while cross-topic generalisation collapses (0.79 → 0.39 → 0.20). Several directions predict utilities; only one generalises across topics.

    

Causally, though, ablating it changes almost nothing. Project the direction out of every token's residual stream and the model's choices agree with baseline 98–99% of the time — including at L23, the steering peak, which rules out the natural "you ablated at the readout layer, not the causal one" objection. A random rank-1 direction at the same layers shifts choices more (0.75–0.96).

    
Adding the direction controls choice; removing it doesn't break anything. The simplest reading is that the choice computation is distributed across enough redundant directions that deleting this one gets routed around, while an arbitrary perturbation disrupts some of what the model is actually using. A weaker reading — rank-1 out of 5,376 dimensions is just too small a poke either way — fits the data too, and would need rank-k ablation to rule out. The paper makes an existence claim, not a uniqueness one.
    

Add the standing caveats the authors list: cross-persona correlation is high but imperfect and some pairs transfer much better than others; personas are mostly prompt-based; steering efficacy is demonstrated on exactly one model. And one open possibility they raise that would reframe the whole result — that shared preference machinery is an artefact of smaller models compressing preference structure into one subspace, while higher-capacity models can afford to keep persona-specific machinery separate.

The claim, in one paragraph

    

A linear probe fit from revealed pairwise task choices onto residual-stream activations recovers a direction that predicts held-out and cross-topic preferences, changes sign when the model's tastes change, scores unrelated things on the same good–bad axis, and — on Gemma-3-27B — causally controls which task gets done. Trained on the default Assistant, it predicts and steers the preferences of six other characters, including one whose tastes run opposite. Preference machinery is at least partly shared across personas; it is not fully shared, no single underlying attractor showed up, and the causal half of the story has so far only been demonstrated on one model.

  
  
    
Glossary
    
      
        
Persona
The character a model simulates while producing text. The default post-trained one is the Assistant; system prompts, fine-tuning and context can install others.
        
Revealed preference
What the model picks when forced to choose, as opposed to what it says it values.
        
Thurstonian utility (μ)
A latent scalar per task, fit by maximum likelihood so that observed pairwise choices are most probable. Meaningful only up to an affine transform.
        
Residual stream
The per-token vector every transformer layer reads from and writes to. 5,376-dimensional on Gemma-3-27B.
        
Linear probe
A regression from activations to a target. Here: ridge from residual-stream activations to utility. Its weight vector is the preference vector.
      
      
        
Steering
Adding c·w to the residual stream during the forward pass, with c expressed as a fraction of the mean activation norm at that layer.
        
Evaluative vs descriptive
Whether a representation encodes how good something is, or what it is. Ice cream as good versus ice cream as cold.
        
Text-encoder baseline
A probe fit on Qwen3-Embedding-8B representations of the same conversation, targeting the same utilities. Has content, lacks the model's internal valuation.
        
Activation patching
Transplanting activations from a donor forward pass into a recipient one, to test whether that site carries the information driving an output.
        
Utility-correlation baseline
The bare correlation between two personas' utilities — what a probe would score if it only ever predicted the training persona's taste.
      
    
  
  
    
      

Source — Oscar Gilg, Pierre Beckmann, Daniel Paleka, Patrick Butlin. Probing Persona-Dependent Preferences in Language Models. arXiv:2605.13339v2 [cs.CL], 18 May 2026. Code at github.com/oscar-gilg/Preferences.

      

About this guide — an explanatory walkthrough, not a substitute for the paper. Statistics are quoted from the text where the text gives them; where a value could only be read off a plotted figure, the instrument's footer says which figure and the values are approximate. Interactive curve shapes are reconstructions fitted to reported endpoints, not the authors' raw data. Transcript excerpts are paraphrased.
