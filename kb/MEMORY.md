# MEMORY.md

Preferences that will not fit a rule. A rule tells an agent what to do; these
tell an agent what the user is like. Add to the list when the user says write
this down and no test attaches to the thing.

- The user works in research mode. They expect findings that upset the first
  guess. If you report that nothing turned up, they will take it as a sign your
  search was too narrow, not as an answer.
- The user wants few turns. Ask less, do more, and state what you assumed.
- The user tests the rules. They will hand over a rule they know is too broad to
  see whether the agent argues back. Argue back. If you say nothing, you failed
  the test.
- When the user hands a judgment call back — "your choice how to resolve this" —
  make the call and write it into `constitution.md`. Do not answer with a list
  of options.
- The user cares about their own wording. When they hand over a block of text to
  keep, they mean every word of it, and the punctuation too.
- The user holds answers to the same writing rules as the files. Metaphors in a
  reply count as a failure, even when the files are clean.

- The user wants agency, including moves they did not ask for. Publishing a
  finished deliverable as an artifact and handing over the link was called "the
  kind of unexpected agency I need". So when work is done and has an audience,
  ship it and give them the link. Do not ask first.
